# SK-004 | Host a private knowledge library

Category: Deployment examples | Keywords: private deployment, Caddy, Authelia, Docker Compose, Cloudflare Tunnel.

First recorded: 2026-11-11 | Last updated: 2026-11-11 | Last reviewed: 2026-11-11

**Question:** How do I host HumblePen on Ubuntu, require readers to sign in, and publish updates from a private repository?

## Answer and example

The server fetches `main` from a private repository, builds in an isolated container, and switches to the validated output. Browser requests reach Caddy through Cloudflare Tunnel. Caddy checks authorization with Authelia before serving notes, page scripts, search indexes, or the asset manifest. An example sign-in URL is `https://knowledge.example.com/auth/`. Readers use a password and TOTP. Their access is managed separately from GitHub repository access.

### 1. Prepare the server and read-only repository access

Install Docker Engine with Compose, Git, SSH, Python 3.10+, and OpenSSL. Prepare a dedicated hostname managed by Cloudflare and an SMTP account. The server needs access to GitHub, package and image registries, SMTP, and Cloudflare Tunnel. Copy the template to your own private repository and keep GitHub Pages disabled.

Run the commands in a Bash session with administrative access on the server. Replace the example paths, hostname, and repository with your values. Use the SSH clone URL from GitHub. Keep the three directories separate and use paths without spaces.

```sh
umask 077
HP_STACK=/path/to/private-config
HP_DATA=/path/to/site-data
HP_SOURCE=/path/to/source-checkout
HP_HOST=knowledge.example.com
HP_REPOSITORY='<GITHUB_SSH_URL>'
```

Create the private directories and a dedicated, read-only SSH deploy key.

```sh
install -d -m 700 "$HP_STACK" "$HP_DATA"
ssh-keygen -t ed25519 -N '' -C 'humblepen-readonly' -f "$HP_STACK/github_deploy_key"
ssh-keyscan -t ed25519 github.com > "$HP_STACK/known_hosts.pending"
ssh-keygen -lf "$HP_STACK/known_hosts.pending"
```

Check the fingerprint and rename the pending file to `known_hosts`. Add the public key in `github_deploy_key.pub` under **Settings → Deploy keys** on GitHub and leave write access disabled. Keep the private key on the server. [GitHub SSH fingerprints](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints) · [GitHub deploy keys](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys)

```sh
mv "$HP_STACK/known_hosts.pending" "$HP_STACK/known_hosts"
export GIT_SSH_COMMAND="ssh -i $HP_STACK/github_deploy_key -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes -o UserKnownHostsFile=$HP_STACK/known_hosts"
git clone --branch main --single-branch "$HP_REPOSITORY" "$HP_SOURCE"
```

### 2. Install and configure the private runtime files

```sh
install -d -m 700 "$HP_STACK/authelia" "$HP_STACK/auth-data" "$HP_STACK/secrets"
HP_FILES="$HP_SOURCE/deploy/server"
install -m 600 "$HP_FILES/compose.yml" "$HP_FILES/Caddyfile" "$HP_FILES/update.py" "$HP_STACK/"
install -m 644 "$HP_FILES/probe-internal.py" "$HP_STACK/"
install -m 600 "$HP_FILES/runtime.env.example" "$HP_STACK/.env"
install -m 600 "$HP_FILES/update.example.json" "$HP_STACK/update.json"
install -m 600 "$HP_FILES/authelia.example.yml" "$HP_STACK/authelia/configuration.yml"
install -m 600 "$HP_FILES/users.example.yml" "$HP_STACK/authelia/users.yml"
for key in session_secret storage_key reset_secret; do
  openssl rand -hex 32 > "$HP_STACK/secrets/$key"
done
touch "$HP_STACK/secrets/smtp_password" "$HP_STACK/secrets/tunnel_token"
```

- Set `SITE_HOST` and `SITE_DATA_ROOT` in `.env` to match `HP_HOST` and `HP_DATA`.
- Replace the example domain and SMTP settings in `authelia/configuration.yml`. Use your provider's STARTTLS address, authorized sender, account, and test recipient. Use an editor to write the SMTP credential to `secrets/smtp_password`.
- Generate an Argon2id hash with the interactive command below. Edit `users.yml` and give each reader a separate account, a single-quoted hash, a working email address, and membership in the `readers` group.

```sh
docker run --rm -it authelia/authelia:4.39.28 authelia crypto hash generate argon2
chown -R 1000:1000 "$HP_STACK/authelia" "$HP_STACK/auth-data"
chown 1000:1000 "$HP_STACK/secrets/"{session_secret,storage_key,reset_secret,smtp_password}
chmod 600 "$HP_STACK/secrets/"{session_secret,storage_key,reset_secret,smtp_password}
```

Keep actual configuration, email addresses, notification credentials, and the authentication database in the server's private directory. [Authelia SMTP](https://www.authelia.com/configuration/notifications/smtp/) · [Authelia secrets](https://www.authelia.com/configuration/methods/secrets/)

### 3. Build in isolation and verify internal access controls

```sh
docker pull node:22-bookworm-slim
HP_BASE_IMAGE=$(docker image inspect --format '{{index .RepoDigests 0}}' node:22-bookworm-slim)
docker build --build-arg NODE_BASE_IMAGE="$HP_BASE_IMAGE" \
  -f "$HP_FILES/Dockerfile.builder" -t humblepen-builder:node22 "$HP_FILES"
HP_IMAGE=$(docker image inspect --format '{{.Id}}' humblepen-builder:node22)
printf '%s\n' "$HP_IMAGE"
```

In `update.json`, enter the SSH repository URL, hostname, deploy-key and `known_hosts` paths, data directory, runtime directory, and full `sha256:` image ID. The updater uses the local image you built. Repository code runs in a temporary container without the GitHub private key, Authelia secrets, or the Docker socket.

```sh
cd "$HP_STACK"
docker compose config --quiet
python3 update.py --config update.json --bootstrap
docker compose pull caddy authelia
docker compose run --rm --no-deps caddy caddy validate --config Caddyfile --adapter caddyfile
docker compose run --rm --no-deps authelia authelia config validate --config configuration.yml
docker compose up -d caddy authelia
docker compose ps
```

When Authelia is healthy, run the checks from the internal network. The commands use the template's Chinese and English note URLs. If you replaced those notes, use URLs from the current release. The probe also checks both search indexes.

```sh
HP_NOTE=docs/skills/SK-001.html
HP_EN_NOTE=en/docs/skills/SK-001.html
HP_PROBE=/path/to/probe-internal.py
HP_SEARCH=$(find -L "$HP_DATA/public/current/assets/chunks" -name '@localSearchIndexroot.*.js' -print -quit)
HP_EN_SEARCH=$(find -L "$HP_DATA/public/current/assets/chunks" -name '@localSearchIndexen.*.js' -print -quit)
test -n "$HP_SEARCH" && test -n "$HP_EN_SEARCH"
HP_SEARCH=${HP_SEARCH#"$HP_DATA/public/current"}
HP_EN_SEARCH=${HP_EN_SEARCH#"$HP_DATA/public/current"}
hp_probe() {
  docker run --rm --network private-knowledge_entry \
    --mount "type=bind,src=$HP_STACK/probe-internal.py,dst=$HP_PROBE,readonly" \
    "$HP_IMAGE" python3 "$HP_PROBE" "$HP_HOST" "/$HP_NOTE" "/$HP_EN_NOTE" "$HP_SEARCH" "$HP_EN_SEARCH" "$@"
}
hp_probe
docker compose stop authelia
hp_probe --expect-outage
docker compose up -d authelia
```

Wait for Authelia to recover, then run `hp_probe` again. Connect the public hostname only after the test confirms that anonymous requests, forged identity headers, and an authentication outage all leave content inaccessible. The Compose configuration publishes no host ports for Caddy or Authelia. [Authelia's Caddy integration](https://www.authelia.com/integration/proxies/caddy/)

### 4. Connect the tunnel and test reader accounts

Create a remotely managed tunnel in Cloudflare. On the private server, write its token to `secrets/tunnel_token` with an editor, then start the connector.

```sh
chown 65532:65532 "$HP_STACK/secrets/tunnel_token"
chmod 400 "$HP_STACK/secrets/tunnel_token"
docker compose --profile tunnel up -d cloudflared
docker compose --profile tunnel ps
```

Configure a cache bypass for every path on the site's hostname. Enable HTTPS and point the hostname's application route to `http://caddy:8080` on the Docker network. Check that DNS points only to this tunnel. Keep Caddy's access checks and private response headers in place. [Create a Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/) · [Cloudflare Cache Rules](https://developers.cloudflare.com/cache/how-to/cache-rules/)

```sh
python3 update.py --config update.json --probe
```

In a private browser window, confirm that unauthenticated requests for notes, page scripts, search indexes, and the asset manifest are denied or redirected to the site's sign-in page. Sign in with a separate reader account, enroll TOTP, and verify search in both languages, direct page reloads, and sign-out. Disable a test reader, restart Authelia, and make a fresh request to verify the old session no longer works. If an anonymous public request returns content, stop Caddy immediately, disable the tunnel route for that hostname, and repeat the internal checks.

### 5. Enable automatic updates and prepare for rollback

Once the public entry point and reader accounts pass verification, install `knowledge-update.service` and `knowledge-update.timer`. Replace `/path/to/private-config` in the service with the actual `HP_STACK` path, then install both units in the systemd system-unit directory.

```sh
sed "s|/path/to/private-config|$HP_STACK|g" "$HP_FILES/knowledge-update.service" > "$HP_STACK/knowledge-update.service"
HP_SYSTEM_CONF=$(systemd-path system-configuration)
install -m 644 "$HP_STACK/knowledge-update.service" "$HP_FILES/knowledge-update.timer" "$HP_SYSTEM_CONF/systemd/system/"
systemctl daemon-reload
touch "$HP_DATA/updates-enabled"
systemctl start knowledge-update.service
systemctl enable --now knowledge-update.timer
```

Push a reviewed test note and check `systemctl list-timers knowledge-update.timer`, the service logs, and `readlink "$HP_DATA/public/current"`. The updater checks anonymous access before and after publishing. If authentication fails, it attempts to stop Caddy. Confirm that access is closed before investigating the cause and the active release.

For a rollback, pause the timer, remove `updates-enabled`, and confirm the update service has exited. Use the full SHA of a retained release.

```sh
systemctl stop knowledge-update.timer
rm -f "$HP_DATA/updates-enabled"
systemctl is-active knowledge-update.service
python3 "$HP_STACK/update.py" --config "$HP_STACK/update.json" --rollback '<COMMIT_SHA>'
```

Proceed with the rollback when `systemctl is-active` reports `inactive`. The rollback uses the current identity and authorization settings. Before re-enabling updates, confirm the intended content is in `main` in the private repository, then restore the update marker and start the timer. Back up server configuration, keys, and Authelia data privately. Pause database writes before backing up the database. Repeat the access checks after upgrading Caddy, Authelia, or the updater. Before upgrading an existing single-language deployment, install the matching `deploy/server/update.py` in the private runtime directory so the validator accepts English pages.

## When to use it

Use this approach if you have an Ubuntu server, a Cloudflare-managed domain, and an SMTP service, and want separate reader accounts with two-factor authentication. The operator is responsible for the server and authentication data. For content you intend to share publicly, see the [GitHub Pages example](./SK-003.md).
