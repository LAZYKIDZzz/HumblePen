# SK-003 | Publish a public knowledge library with GitHub Pages

Category: Deployment examples | Keywords: GitHub Pages, GitHub Actions, VitePress, public deployment.

First recorded: 2026-11-11 | Last updated: 2026-11-11 | Last reviewed: 2026-11-11

**Question:** How do I publish HumblePen with GitHub Pages so readers can search notes and open them directly?

## Answer and example

1. Create a public repository from the template and use `main` as the default branch.
2. In **Settings → Pages**, set **Build and deployment → Source** to **GitHub Actions**.
3. Under **Settings → Secrets and variables → Actions → Variables**, create a repository variable named `PAGES_ENABLED` with the value `true`.
4. In **Actions → Publish public GitHub Pages**, select **Run workflow** and choose `main`. Subsequent pushes to `main` trigger a deployment.
5. Open the site URL shown in the Pages settings. Switch to English from the language menu, then open this note from **Deployment examples** and reload the page to test the direct link. Search for “fixed string” and open a result. Copy the URL from the browser to share a note.

The workflow reads the site's base path from GitHub Pages and uploads only the validated `.vitepress/dist` output. A repository subpath and a custom domain use the same site configuration. Run the workflow again after configuring a custom domain. Pull requests run build checks.

To pause updates, remove `PAGES_ENABLED` or set it to `false`. To take the existing site offline, unpublish it in the Pages settings.

## When to use it

Use Pages for content you intend to share publicly. Readers can access notes and commit history in the public repository, along with the site's page data and search indexes. Review the full repository before the first push. For access restricted to authorized accounts, follow the [private server example](./SK-004.md).
